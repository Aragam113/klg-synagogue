# 0006. Локализация: jsonb `{ru,en,he}` с фолбэком на ru, длинные тексты — в коде, иврит машинный

## Контекст

Пользователь выбрал «Русский + English + иврит». Редактор пишет по-русски и переводит не всегда. Иврит — RTL, носителя в команде нет. Длинные тексты разделов (история, правила, «Туристам») структурированы: таймлайн, цитаты с источником, фото.

## Решение

Каждое переводимое поле в БД — jsonb `{ru: string, en?: string, he?: string}`, где `ru` обязателен. API принимает `?lang=` и отдаёт строку на запрошенном языке или русскую с `fallback: true`, а фронт показывает пометку «Доступно на русском». Интерфейс переводится через i18next (неймспейсы `locales/<lang>/<ns>.json`). Длинные статические тексты лежат в типизированных файлах `frontend/src/content/<lang>/*.ts`, а не в БД. Иврит во всех статических текстах — машинный перевод, помеченный «нужна вычитка носителем». RTL делается через `dir` на `<html>` и логические CSS-свойства.

## Почему

- **Отдельная таблица переводов или строка на каждый язык.** Отвергнуто: языков ровно три, и они фиксированы. Join на каждом списке, синхронизация слагов и статусов между строками и сложная админка ничего не дают по сравнению с тремя ключами в одном поле.
- **Обязательные переводы на все языки.** Отвергнуто: редактор перестанет публиковать новости, а импорт из Telegram (ADR 0009) даёт только ru.
- **Длинные тексты в БД с редактированием из админки.** Отвергнуто: это структурированные документы с таймлайном и цитатами, и для них понадобился бы конструктор страниц. Как ts-модули они типизированы, а тест проверяет паритет трёх языков.
- **Сайт без иврита до профессионального перевода.** Отвергнуто: язык заказан. Машинный перевод с явной пометкой лучше, чем ничего, и честнее, чем выдавать его за вычитанный.

## Последствия

- Поменять текст истории или правил может только разработчик с деплоем. Через админку это не делается.
- До вычитки носителем иврит может содержать ошибки, в том числе в религиозной терминологии, на которую аудитория чувствительна.
- Четвёртый язык означает правку типа `LocalizedString`, DTO, админских вкладок и всех файлов `content/` и `locales/`. Миграция данных не нужна.
- Поиск по контенту идёт по jsonb для текущего языка. Непереведённое на en/he находится только через фолбэк.
